# DXF 导入判断实施验收

2026-10-13，当前分支 `codex/dxf-workbench`。实施依据为[导入判断方案](../superpowers/specs/2026-10-13-dxf-import-judgment-design.md)。状态：三个阶段、独立复核及最终验收完成。

## 实际文件验收

对用户提供的 DXF 执行本机只读验收，没有复制为公开测试样例。端点处理使用物理毫米坐标，不存在针对文件 handle、图层名或尺寸的修复分支。

| 检查 | 结果 |
| --- | --- |
| 模型空间图形 | 54 个有效区域 |
| 自动归一 | 6 项，保留原始路径和修改记录 |
| 板材 | 2 张，各 1220 × 2440 mm |
| 全部零件 | 42 件 |
| 原位置 | 第一板 32 件，第二板 7 件 |
| 待放置 | 3 件，保留源图位置 |
| 零件模式 | 42 件、0 板材、0 放置 |
| 追加两次来源 | 84 件、78 个原位置、6 个待放置，ID 无冲突 |
| 恢复与撤销 | 恢复 39 个原位置、3 个待放置；撤销恢复操作前布局 |
| 不完整导出 | 被阻止 |
| 原文件 | SHA-256 验收前后相同 |

验收显式将六个已说明用途的轮廓设置为槽区域，另外四个内部轮廓设置为通孔，得到 **4 孔 / 6 槽**。这里的四个通孔是测试选择，不是系统自动判定。槽深 6 mm、板厚 18 mm 和材质也只用于验证输入与校验，不能据此认定原图实际加工参数。

板材和待放置件使用不同的测试材质，确认后独立保留，证明没有自动继承邻近板材参数。归一记录对应 20D、20E、214、21B、21E、229；待放置来源对应 21D、23E、240。源文件 SHA-256：`8c9215d0de6e386c9c1bb776a65d703ac2fdeba6f8089663b78695f99d834b20`。

## 阶段验证

- 几何归一：覆盖端点容差边界、mm/cm/inch、块缩放和 OCS、真实 bulge、椭圆和样条、唯一链匹配、分支与资源约束、原路径恢复、中心路径解释。任务复核发现椭圆遗漏和密集候选内存风险，两项修复后复核通过。
- 混合导入：26 项新增行为回归，覆盖框外件、跨板/多板归属、旋转板、待放置孔槽与标签、独立元数据、追加和撤销、原位置恢复、不完整导出。覆盖检查共 233 项通过，构建通过。
- 既有示例：3 板、53 件、53 个原位置、28 孔、29 槽保持不变。
- 集中核对：上传默认未知，建议明确应用；覆盖组合图层词、凹轮廓完整包含、板框候选、模板优先级、批量子集、来源归宿及多问题分组。任务复核发现批量默认画法与实际载荷不一致，修复后复核通过。

## 最终检查

实际文件浏览器验收：默认 54 个对象均未确认，集中成 4 个图层问题组；6 条归一记录默认折叠。明确设置图层后，勾选六个槽区域批量填写测试深度，得到 2 板 / 42 件 / 39 已放置 / 3 待放置。缺少框外件元数据会阻止确认并定位输入框；显式复制所选板材参数后，框外件仍可独立更换材质，工作区中保留该材质。

原单位重读后，手工用途、测试槽深和分别填写的板材/框外件参数保留。切换零件模式得到 42 件、0 板材、全部待放置；模式改变会清空需重新确认的元数据。确认整板导入后工作区显示 39 / 42；不完整导出的下载按钮禁用，撤销导入返回原工作区。上传 `sample.dxf` 先显示 113 个未确认对象，主动选择兼容预设后恢复 3 板 / 53 件 / 28 孔 / 29 槽。

桌面及 320 px 视口均无页面横向溢出，窄屏批量设置和输入控件未超出边界。验收后重置浏览器视口，不改动用户已有标签页。截图：[桌面预览](../design/import-judgment-confirmed.png)、[窄屏](../design/import-judgment-mobile.png)、[窄屏批量设置](../design/import-judgment-mobile-batch.png)。截图参数为验收输入，不是原图加工确认。

最终完整测试：`pnpm exec vitest run --maxWorkers=1 --no-file-parallelism`，29 文件 / **447 项通过**，退出 0；`pnpm build` 与 `git diff --check` 通过。全量命令曾误扫描忽略目录中的复查快照，产品测试通过但快照相对导入失败；所有快照统一使用非测试扩展名后，重新执行上述完整命令通过。未改变测试配置或产品实现来绕过检查。

最终整体复查发现两项问题：非槽用途仍受隐藏中心路径设置影响，以及同层不同板框建议使用重复 React key。两项均有失败回归，修复后独立复核通过；覆盖 78 项测试及构建通过。修复后干净浏览器页面逐一接受包含 32 件与 7 件的板框建议，剩余卡片和来源对应正确；原始中心路径切换为通孔后重新使用归一几何，不再出现错误的开放路径阻断。全流程无浏览器 warning/error，最终实际文件再次得到 54 / 6 / 2 / 42 / 39 / 3，追加、恢复、撤销、缺件导出和源文件哈希检查仍通过。
