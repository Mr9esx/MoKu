# 通用 DXF 导入方案 · 2026-10-12

状态：2026-10-12 已实施。任意图层先进入文档与几何草稿，再核对用途并确认导入；未添加 TOP-CUT-INSIDE 特例。实现和验证见 dxf-import-implementation.md、docs/verification.md。

## 根因

重构前 `src/core/dxf.ts` 把文件解码、几何归一、工艺分类、板框推断、编号关联和 Project 构建耦合在一次解析中。实体和图层在预览前就被严格拒绝；因此加工含义未知也被误报成“文件不能读取”。

- 所有几何图层必须以 CUT / HOLE / POCKET / REF_STOCK 开头；任意合法的 CAD 图层名称无法进入预览。
- 内部 CUT 轮廓直接拒绝，而不是保留几何并要求核对工艺。
- 安装的 dxf-parser 本身有 INSERT、ELLIPSE、SPLINE、DIMENSION 等实体解码器，但应用白名单及几何转换仅接受少数类型。
- HATCH 被整体忽略，编号关联只针对 P 数字，板厚来自特定图层后缀。这些都是示例习惯，不应成为通用读取条件。

`TOP-CUT-INSIDE_18.000MM` 不是非法 DXF 图层。TOP、CUT、INSIDE 和 18.000MM 可以作为建议的证据，但没有源软件的规范或用户确认，不能断定 INSIDE 是通孔，也不能确定 18 是板厚或槽深。

## 推荐架构

DXF 文件 → 原始文档 → 归一几何 → 导入核对草稿 → 已确认 Project → 现有 SVGnest / 独立几何校验。

### 原始文档

使用成熟库解码实体、块、图层、单位、模型/布局空间和属性。保存原始图层、实体 handle、块实例路径、空间和诊断。图层名称不决定能否读取。

### 归一几何

- 明确选择模型空间或一个布局，避免把同一零件从不同空间重复导入。布局视口是显示对象，不能转成加工轮廓。
- 展开嵌套 INSERT，应用块基点、实例平移/旋转/缩放/镜像及图层继承；不同实例有独立且稳定的标识。
- 统一单位和坐标系，正确处理常见平面 OCS；非平面加工几何不能静默投影成二维。
- LINE / ARC 链、闭合多段线、圆、椭圆、样条统一为带来源的曲线/路径；排版需要的多边形按统一物理误差采样，先做复杂度检查。显示线段和切割轮廓不能共用未经核验的精度假设。
- 包含关系建立外/内轮廓候选，重复边界、自交、开放链和分支保留诊断。不能把每个内环自动当作孔，也不能把每个最大的矩形自动当作板材。
- HATCH 可作为显示或边界候选，不能因其存在就自动推断为槽；与已存在的边界避免重复计数。

### 工艺核对

草稿保存“未知”工艺，而不是提前强行构造 `Part.holes` 或 `Part.pockets`。

- 图层名、颜色、块属性、显式深度等只形成建议并注明依据。兼容现有示例约定，但约定作为预设配置而非读取白名单。
- 用户按图层批量确认：外轮廓、通孔、槽、板框、辅助线；同一图层混有不同用途时允许按单个轮廓覆盖。
- 槽深、板厚、材质分开输入；没有单位或工艺信息就要求核对，不把数字后缀或 Z 坐标擅自当成槽深。正反面信息若存在须保留；当前产品不能表达的工艺需指出而非丢弃。
- 可保存命名的导入配置，下次同来源图纸先预填建议，仍显示预览和异常。

### 界面

先显示源图、空间与读取摘要，再仅针对未确定内容展开核对。

图层表包含名称、轮廓数量、建议用途、确认用途、必要的深度/厚度。点击行高亮对应几何，支持批量确认；常见图纸明确后可直接确认，不要求逐件配置。未知名称不能阻止预览。

读取异常分为：显示/辅助对象（记录忽略）、待确认的加工对象（可预览但暂不提交）、必需轮廓的读取失败（定位并阻止提交）。不能以“成功导入”掩盖漏件或漏孔；用户明确排除的辅助内容不构成失败。

### Project 构建

确认之后才将外轮廓、通孔和槽转换为现有领域模型。保留源坐标与证据；沿用板厚、材质、间距、独立验证、追加/新建和撤销事务。取消核对不改工作区。

## 开源方案比较

| 方案 | 已核实能力 | 判断 |
| --- | --- | --- |
| dxf-parser + 独立几何/工艺导入层 | 当前已安装，能解码常见二维实体、块/INSERT、图层和部分属性。现有适配层未使用全部能力。 | 符合当前浏览器 Worker、本地处理约束；推荐先用于新导入架构的解码层，几何能力必须经过验证，不继续扩展旧的一体化 parseDxf。 |
| dxf-viewer | 浏览器 WebGL 展示、Worker、块实例、图层；自身也使用 dxf-parser，并明确列出布局、任意 OCS 等限制。 | 可用于源图展示对照，不能把渲染三角形或屏幕线段直接当加工轮廓，也不能替代工艺核对。 |
| ezdxf | 明确的模型/布局访问、嵌套块分解、统一 Path、样条/椭圆、修复与诊断。 | 更完整的 CAD 几何候选和对照来源；Python 部署与浏览器本地运行成本需实测。此次未验证可直接用于本项目的浏览器 Worker，不能承诺无代价替换。 |

不以“库能显示某实体”作为“可可靠加工”的依据。任何库都不能从缺失的信息里确定二维内轮廓是通孔还是浅槽。

## 实施顺序与验收

1. 先建立不依赖图层名的文档/几何草稿，移除“未知图层就文件失败”的架构条件，加入图层批量映射和未知内环核对。现有约定作为兼容预设。
2. 在新几何层验证块实例、样条/椭圆、平面坐标变换、模型/布局筛选；用真实输出对照决定是否需更换解码库，而不是把新增实体塞进旧白名单。
3. 建立多来源 CAD 文件验收集合：匿名图层、任意名称、用户此次 TOP-CUT-INSIDE、现有示例、嵌套块/镜像/非均匀缩放、混合显示对象、开放链、孔槽同层、内嵌独立零件、重复轮廓、单位缺失和非平面几何。
4. 验收几何尺寸、面积、坐标、零件/孔槽数量和每个源实体的归宿；检查无静默遗漏，提交/取消/重解析/撤销一致。首个失败实体不应遮蔽其余可以核对的内容。

已拿到的是图层错误文本，尚未拿到该用户 DXF 原文件；无法据此确认其完整实体结构、轮廓数量或加工约定。实施时需以源文件和多来源集合验证，不将此名称直接写成规则。
